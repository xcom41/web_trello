# Учебное окружение: nginx + php-fpm + PostgreSQL

Простой стек для практики Docker Compose: nginx как веб-сервер и реверс-прокси к PHP-FPM 8.5 (чистый PHP, без фреймворков), PostgreSQL 18 как база данных. Все три образа собираются локально из Dockerfile в `docker/`.

## Быстрый старт

```bash
make init && make up && make composer
```

- `make init` создаёт `.env` из `.env.example` и подставляет в него UID/GID текущего пользователя. Это необходимо, чтобы файлы, которые создаёт PHP-контейнер, на хосте принадлежали пользователю, а не `root`.
- `make up` собирает образы, если они ещё не собраны, и запускает контейнеры.
- `make composer` устанавливает зависимости приложения в `app/vendor/`.

После запуска:

- **Приложение:** http://127.0.0.1:8080/
- **Health-check:** http://127.0.0.1:8080/health.php
- **PostgreSQL:** `127.0.0.1:5432`

Подключиться к PostgreSQL можно через любой GUI-клиент, используя логин, пароль и имя базы из `.env`, либо командой `make psql`.

Остальные команды перечислены в `make help`.

## Eloquent ORM

**Eloquent ORM** используется для работы с PostgreSQL через PHP-модели, упрощая выполнение операций с данными без необходимости вручную писать SQL-запрос для каждой операции.

Для подключения используются библиотеки:

- `illuminate/database` — ORM и работа с базой данных;
- `illuminate/events` — поддержка событий, необходимых компонентам Illuminate.

Параметры подключения к PostgreSQL задаются через переменные окружения `DB_*` в `.env`.

## Логирование с Monolog

**Monolog** — библиотека для записи событий и ошибок приложения в журналы.

Логгер настраивается в `src/LoggerFactory.php`. Предусмотрена запись информации об HTTP-запросах, кодах ответов, времени обработки и ошибках.

Основной файл журнала:

```text
storage/logs/app.log
```

Логирование помогает диагностировать ошибки и отслеживать работу приложения.

## Конфигурация и шифрование

Класс `src/Config.php` предназначен для загрузки и обработки конфигурационных параметров приложения, в том числе зашифрованных значений.

Для шифрования используется алгоритм **AES-256-GCM**, обеспечивающий конфиденциальность и проверку целостности данных.

Ключ шифрования задаётся через переменную окружения `APP_CONFIG_KEY`. Его необходимо хранить отдельно от зашифрованных данных и не добавлять в репозиторий.

## Таблицы базы данных

PostgreSQL используется для хранения пользователей, досок и задач приложения.

Основные таблицы:

- **`users`** — пользователи приложения и их данные.
- **`boards`** — доски, создаваемые пользователями.
- **`board_columns`** — колонки внутри досок, например «К выполнению», «В работе» и «Готово».
- **`cards`** — карточки задач, размещённые в колонках.

Связи между таблицами реализуются с помощью первичных и внешних ключей:

- доски связываются с пользователями;
- колонки связываются с досками;
- карточки связываются с колонками.

Такая структура позволяет организовать задачи по доскам и колонкам, а также поддерживать целостность связанных данных.

## Миграции базы данных

Миграции предназначены для создания и изменения структуры PostgreSQL с помощью PHP-скриптов.

Основные компоненты:

- `src/Migration/Migrator.php` — управление выполнением миграций;
- `bin/migrate.php` — запуск миграций из командной строки;
- таблица `migrations` — учёт уже применённых миграций;
- `migrations/2026_10_12_000001_create_demo_table.php` — пример миграции для создания демонстрационной таблицы `demo`.

Запуск:

```bash
php bin/migrate.php
```

Миграции позволяют последовательно изменять структуру базы данных и отслеживать применённые изменения.

## Когда пересобирать, а когда достаточно F5 или restart

- **Изменения в `app/`** — PHP-код обновляется сразу благодаря подключению каталога как volume. В режиме разработки OPcache настроен на проверку изменений при каждом запросе (`opcache.validate_timestamps = 1`, `opcache.revalidate_freq = 0`). Достаточно обновить страницу.
- **Изменения конфигурационных файлов** — файлы в `docker/nginx/conf.d/`, `php.ini`, `www.conf` и `postgresql.conf` подключены как volume, но для применения настроек обычно требуется перезапустить соответствующий сервис.
- **Изменения Dockerfile или `app/composer.json`** — требуется пересборка образов командой `make build`. После изменения зависимостей Composer необходимо также выполнить `make composer`.

Пример перезапуска отдельных сервисов:

```bash
docker compose restart nginx
docker compose restart php
docker compose restart postgres
```

Названия сервисов должны соответствовать тем, которые указаны в `compose.yaml`.

## Ловушка: initdb выполняется только один раз

SQL-скрипты из `docker/postgres/initdb/*.sql` выполняются только при инициализации пустого тома `pgdata`, то есть при первом запуске PostgreSQL с этим томом.

Если окружение уже запускалось и файл `01-init.sql` был изменён, изменения не применятся автоматически.

Для повторной инициализации можно выполнить:

```bash
make clean && make up
```

**Внимание:** эта операция удаляет том PostgreSQL и все хранящиеся в нём данные. Перед выполнением необходимо создать резервную копию, если данные важны.

Для обычных изменений схемы существующей базы предпочтительно использовать миграции.

## Linux / macOS / Windows (WSL2)

`make init` подставляет реальные UID/GID текущего пользователя в `.env`. Dockerfile PHP пересоздаёт пользователя `www-data` с соответствующими идентификаторами, чтобы файлы, создаваемые контейнером, принадлежали пользователю на хосте.

- **Linux:** bind mount напрямую передаёт права и владельца файлов.
- **macOS:** Docker Desktop с virtiofs поддерживает работу с владельцами файлов.
- **Windows + WSL2:** команды `make` и `docker compose` следует запускать из терминала WSL2, а проект хранить внутри файловой системы Linux, например `~/projects/`, а не в `/mnt/c/`.

Также необходимо включить WSL-интеграцию для используемого дистрибутива в Docker Desktop: **Settings → Resources → WSL Integration**.

Файл `.gitattributes` принудительно задаёт окончания строк LF, чтобы Git не заменял их на CRLF в Dockerfile, Makefile и конфигурационных файлах.

## Структура проекта

```text
app/                 — PHP-код приложения
  src/               — исходный код, включая модели и конфигурацию
  vendor/            — зависимости Composer
docker/
  nginx/             — Dockerfile и конфигурация nginx
  php/               — Dockerfile, php.ini и конфигурация PHP-FPM
  postgres/          — Dockerfile, postgresql.conf и init-скрипты
compose.yaml         — конфигурация Docker Compose
.env.example         — пример переменных окружения
Makefile             — команды управления окружением
```

Автозагрузка классов приложения настроена по стандарту PSR-4: пространство имён `App\` соответствует исходному коду в `app/src/`.

## Основные команды

```bash
make help       # список доступных команд
make init       # подготовка .env
make build      # сборка образов
make up         # запуск окружения
make composer   # установка PHP-зависимостей
make psql       # подключение к PostgreSQL
make clean      # очистка окружения с удалением данных PostgreSQL
```

Назначение и точное поведение команд определяются текущим `Makefile`.
